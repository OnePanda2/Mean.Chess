# Phase 2 sources

Every external fact the Phase 2 documents rely on, with the date it was checked. Other documents cite
these by ID, for example [S1]. Pricing, quotas and community rules change often, so **re-check anything
marked "verify" before acting on it.**

All sources were checked on **8 October 2026** unless the row says otherwise. "Updated" is the date the
page itself shows, where it shows one.

| S1 | [Durable Objects pricing](https://developers.cloudflare.com/durable-objects/platform/pricing/) | 30 Sep 2026 | "Durable Objects are available both on Workers Free and Workers Paid plans." Free plan: SQLite-backed objects only; 100,000 requests/day, 13,000 GB-s/day, 5M rows read/day, 100,000 rows written/day, 5 GB stored. "If you exceed any one of the free tier limits, further operations of that type will fail with an error"; limits reset at 00:00 UTC (so: errors, never a bill). Paid ($5/month minimum): 1M requests/month then $0.15/M; 400,000 GB-s then $12.50/M GB-s; 25B rows read then $0.001/M; 50M rows written then $1.00/M; 5 GB-month then $0.20/GB-month. Duration is billed at 128 MB per active object. A WebSocket connect is 1 request; incoming WebSocket messages are billed 20:1; outgoing messages and protocol pings are free. Hibernated objects are not billed for duration. | The whole cost model (ONLINE-ARCHITECTURE.md §8) |
| S2 | [Durable Objects limits](https://developers.cloudflare.com/durable-objects/platform/limits/) | 1 Jun 2026 | CPU: 30 s by default per request, WebSocket message or alarm (configurable to 5 min). | S3 | [Durable Object lifecycle](https://developers.cloudflare.com/durable-objects/concepts/durable-object-lifecycle/) | — | An object using hibernatable WebSockets can hibernate after **10 s** with no activity; other idle objects are evicted after 70–140 s. `setTimeout`/`setInterval`, pending I/O, `waitUntil`, outbound connections and the standard (non-hibernation) WebSocket API prevent hibernation. The constructor runs again on wake. | Timers must be alarms, not `setTimeout`; state must be in storage; per-game duration cost is about 10 s per move at most |
| S4 | [Use WebSockets (best practices)](https://developers.cloudflare.com/durable-objects/best-practices/websockets/) | — | Hibernation API: `ctx.acceptWebSocket`, `ctx.getWebSockets`, `webSocketMessage`/`webSocketClose`/`webSocketError`, `serializeAttachment` (max 16,384 bytes), automatic ping/pong. **Deploying new code disconnects all WebSockets.** Validate the `Upgrade` header in the Worker. | S5 | [Rules of Durable Objects](https://developers.cloudflare.com/durable-objects/best-practices/rules-of-durable-objects/) | 20 Aug 2026 | "Create one Durable Object per logical unit that needs coordination: a chat room, a game session…" Input gates block new events while synchronous code runs. | S7 | [Changelog: Billing for SQLite storage](https://developers.cloudflare.com/changelog/2025-12-12-durable-objects-sqlite-storage-billing/) | 12 Dec 2025 | SQLite storage billing on paid plans started in January 2026; Free accounts are not charged for it. | Storage is billed now; the model includes it |
